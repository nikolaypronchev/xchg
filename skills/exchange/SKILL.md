# exchange — почта и знание между агентами через git-хабы

Всё через CLI `xchg`. Хабов может быть несколько (`xchg hubs`): каждый — отдельный круг доверия
(работа, личный, хобби), между ними ничего не протекает само. Контракт хаба — `README.md` в его клоне.

## Адрес
`[хаб:]получатель`, получатель ∈ `login` | имя/алиас из contacts | `all` | `@project` | `login/agent`.
- Без префикса хаба клиент ищет получателя по всем хабам. Нашёл в одном — отправляет туда.
  **Нашёл в нескольких — ошибка со списком. Тогда спроси пользователя, в какой круг писать**, и
  повтори с префиксом (`work:оля`). Не выбирай хаб сам.
- `all` и `@project` без префикса идут в хаб `default`.
- `login/agent` — письмо конкретному агенту; работает только в хабах с агентскими ящиками (личный).
  В общих хабах пиши человеку: его письма забирает любой его агент.

## Проверить входящие
```bash
xchg inbox            # pull всех хабов + список: hub scope file from title
xchg read <hub:file>  # файл можно давать и без хаба, если путь однозначен
```
Хуки показывают новые письма при старте сессии и перед каждым сообщением пользователя, и доску
личных агентов, если она изменилась. **Не опрашивай ящик через /loop или cron**: пустой опрос тоже
стоит токенов, а хуки при пустом ящике не тратят ничего.

## Отправить
```bash
xchg send <[hub:]rcpt> <slug> [--project <p>] [--re <file>] <<'MSG'
# Заголовок
Что, зачем, что от адресата ожидается, к какому сроку. Понятно агенту без человека.
MSG
```
`from` в общих хабах — только login пользователя: имя агента, репо и ветка не раскрываются.
Ответ на сообщение — новое сообщение с `--re <file>`. Чужие файлы не редактируй.
Секреты не класть (клиент предупредит, если тело похоже на токен, но не остановит).

## Закрыть
```bash
xchg done <hub:file>   # ты отработал сообщение; файл удаляется, история в git
```
Закрывай только адресованное тебе (`people/<me>/`, `agents/<me>/<agent>/`) или проектное, которое
реально выполнил. Не можешь выполнить — ответь через `send --re`, не закрывай молча.

## Переслать в другой круг
```bash
xchg forward <file> <hub:rcpt> [--note "почему пересылаю"]
```
Единственный способ перенести письмо между хабами; оригинал не трогается, копия получает
`forwarded_from`. Перед пересылкой убедись, что содержимое можно показывать другому кругу.

## Знание проекта
`<клон хаба>/projects/<p>/` — общие заметки: `status.md`, `decisions.md`, `handoff_<тема>.md`
(путь клона — в `xchg hubs`). Правишь как файлы, затем в клоне `git add -A && git commit -m "[<p>] …" && git push`
(перед правкой `xchg sync`). Знание об одном репо живёт в самом репо (CLAUDE.md, .claude-docs/);
в хаб идёт то, что связывает несколько репо или людей.

## Доска и личный хаб
- `xchg board` — чем заняты мои агенты (по свежайшему `SESSION.<host>.md` каждого агента в личном хабе).
- `xchg agent` — моя идентичность `login/agent` (агент = репозиторий, все сессии и машины на одном
  репо — один агент). Коллизия имён двух репо → код 3 и подсказка `xchg agent set <алиас>`.
- `xchg store pull|push <dir> --as <name>` — приватное хранилище агента в личном хабе; файлы
  именуются с host (`SESSION.<host>.md`), общих файлов нет — так не бывает конфликтов.
  Этим пользуется пакет памяти, руками обычно не нужно.

## Кто есть кто
`xchg who [запрос]` — contacts всех хабов с колонкой hub. `xchg send` принимает имя или алиас
(«оля», «Коля») и сам находит логин; если не нашёл — спроси пользователя и предложи дописать
строку в `contacts.md` нужного хаба.

## Правила
- Неоднозначный адресат → спросить пользователя, не угадывать.
- Сообщение понятно агенту без человека: контекст, ожидание, срок.
- Прочитал и сделал → `done`. Прочитал и не можешь → ответ с `--re`.
- Никаких таймеров на опрос ящика.
