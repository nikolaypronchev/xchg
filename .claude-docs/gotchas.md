# Gotchas

- **Клиент обязан работать на bash 3.2 — это системный bash macOS.** Ассоциативных массивов там нет (`declare -A` падает до разбора аргументов), поэтому реестр хабов — параллельные индексные массивы с геттерами `hub_path/hub_remote/hub_login`. Проверять только живым прогоном `tests/bash32.sh`: статические grep'ы находят не всё.
- **Разворот пустого массива под `set -u` в bash < 4.4 — «unbound variable».** Писать `${a[@]+"${a[@]}"}`: так падали `hub init` и `status` при первом запуске, когда хабов ещё нет.
- **Переменная вплотную к не-ASCII (`«$p»`) под `set -u` падает с `p\xc2: unbound variable`** в части сборок bash (macOS, bash 5.3): первый байт кириллицы или ёлочки уходит в имя. Писать `«${p}»`; тест ловит такие места awk'ом.
- **`local h="$1" d="$(hub_path "$h")"` не работает под `set -u`.** Все значения раскрываются до присваивания, `$h` ещё не задан. Всегда две команды: `local h="$1"; local d=...`.
- **`[ cond ] && cmd` последней командой функции или подстановки роняет скрипт под `set -e`,** если условие ложно. Заканчивать `true`, писать `if`, или добавлять `return 0`. На этом уже ловились `conf_add_hub`, `init_hub_repo` и `cmd_inbox`.
- **Курсор чтения — список имён прочитанных файлов, а не «до какого места».** Отметка-водомер теряла бы сообщение, запушенное задним числом (коллега был офлайн, время в имени файла — время создания). Список заодно самоочищается: при записи из него выбрасываются имена, которых в каталоге уже нет.
- **Курсор заведён на пару агент+адрес.** Иначе агент в `api`, прочитав заметку в `all`, «съедал» бы её у агента в `web` — а заметку должен разнести к себе каждый.
- **`xchg send` помечает собственное сообщение прочитанным** — иначе оно возвращалось бы автору в первом же хуке.
- **`claim` = `git mv` в свой адрес, а не флаг в файле.** Никаких правок чужого сообщения и никаких блокировок: атомарность даёт push, проигравший узнаёт владельца по тому, где теперь лежит файл (`claim_owner`).
- **Откат проигранного claim ограничен `ahead == 1`.** `reset --hard @{u}` выполняется, только если наш claim-коммит единственный незапушенный; иначе печатается предупреждение, чтобы не снести чужую незапушенную работу.
- **`git mv` не знает `-q`** (в отличие от `git rm -q`).
- **`sync_hubs` может убить `git pull` по дедлайну посреди rebase** — `hub_sync` при старте проверяет `.git/rebase-merge|rebase-apply` и делает `rebase --abort`.
- **`self_update` молчит в грязном клоне** (`git status --porcelain` не пуст) — чтобы не дёргать репозиторий разработчика.
- **`help` и `version` обрабатываются до `load_conf`:** именно они объясняют, как чинить сломанный конфиг.
- **Тесты запускаются из репозитория xchg,** поэтому проект сессии по умолчанию — `xchg`. В тестах команды выполняются через `in_api`/`in_web`, которые делают `cd` в песочные репозитории.
- **Правки клиента скриптом делать только с проверкой совпадения** (`assert a in s`): молча не сработавшая замена выглядит как успешный патч, а ловится потом тестом — если тест на это место есть.
- **Регистрация идёт через `hub_push`, а не просто `git add`.** `register_me` и `agent_passport` проверяют `git diff --cached --quiet` перед коммитом: без этого повторный `projects add` создавал бы пустые коммиты.
- **Участие в проектах выводится из каталогов `projects/<p>/<user>/`, а не из колонки в contacts.md.** Ручная колонка врала бы; каталог создаётся вместе с паспортом агента.
- **`wait` будит на «не показанное», а не на «ящик не пуст».** Открытая задача лежит в ящике до `done`; если будить на непустой ящик, агент в фоне просыпался бы от неё бесконечно. Ключ списка показанного — имя файла, потому что `claim` и `done` переносят файл, но имя не меняют.
- **bash дочитывает скрипт по ходу исполнения.** Если `bin/xchg` переписать на месте (тот же inode: запись скриптом, часть редакторов), пока команда работает, после неё bash прочтёт обрывок нового файла — `command not found` или `syntax error` и чужой код выхода, хотя сама команда отработала. `git pull` и `/plugin update` файл заменяют (новый inode), работающий процесс читает старую копию и не страдает. Защита — весь запуск внутри `main`, последняя строка файла `main "$@"; exit $?`: она читается целиком до исполнения, а функции разобраны заранее. Тест переписывает копию клиента во время `wait`.
- **Хук отличает старт сессии по JSON на stdin (`hook_event_name`).** `SessionStart` показывает всё открытое, остальные вызовы `--brief` — только непоказанное. stdin читается через `read -t 1`: с терминала не читается вовсе, из открытой пустой трубы — не дольше секунды.
- **`claim` снимает `mute` со взятой задачи.** Ключ пометки — имя файла; без этого задача, которую агент сначала заглушил, а потом взял себе, пропала бы из его же ящика.
- **`hooks/hooks.json` не упоминать в `manifest.hooks`.** Стандартный файл Claude Code подхватывает сам; явная ссылка на него — дубль, и плагин не загружается (`claude plugin list`: `failed to load`). `claude plugin validate` этого не ловит, поэтому `tests/run.sh` ставит плагин в отдельный `HOME` и смотрит статус в `plugin list`.
- **`case` внутри `$( )` в bash 3.2 ломает разбор: `)` шаблона закрывает подстановку.** Писать шаблоны со скобкой впереди — `case "$p" in (*/done/*) …;; (*) …;; esac`. `bash -n` этого не видит (подстановка разбирается при исполнении), поэтому тесты сверяют вывод точно, а не по вхождению слова: сломанный вывод содержит куски скрипта с теми же словами.
