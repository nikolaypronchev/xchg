# Gotchas

- **`local h="$1" d="${HUB_PATH[$h]}"` не работает под `set -u`.** Все значения раскрываются до присваивания, `$h` ещё не задан. Всегда две команды: `local h="$1"; local d=...`.
- **`[ cond ] && cmd` последней командой функции или подстановки роняет скрипт под `set -e`,** если условие ложно. Заканчивать `true`, писать `if`, или добавлять `return 0`. На этом уже ловились `conf_add_hub`, `init_hub_repo` и `cmd_inbox`.
- **Курсор чтения — список имён прочитанных файлов, а не «до какого места».** Отметка-водомер теряла бы сообщение, запушенное задним числом (коллега был офлайн, время в имени файла — время создания). Список заодно самоочищается: при записи из него выбрасываются имена, которых в каталоге уже нет.
- **Курсор заведён на пару агент+адрес.** Иначе агент в `api`, прочитав заметку в `all`, «съедал» бы её у агента в `web` — а заметку должен разнести к себе каждый.
- **`xchg send` помечает собственное сообщение прочитанным** — иначе оно возвращалось бы автору в первом же хуке.
- **`claim` = `git mv` в свой адрес, а не флаг в файле.** Никаких правок чужого сообщения и никаких блокировок: атомарность даёт push, проигравший узнаёт владельца по тому, где теперь лежит файл (`claim_owner`).
- **Откат проигранного claim ограничен `ahead == 1`.** `reset --hard @{u}` выполняется, только если наш claim-коммит единственный незапушенный; иначе печатается предупреждение, чтобы не снести чужую незапушенную работу.
- **`git mv` не знает `-q`** (в отличие от `git rm -q`).
- **`sync_hubs` может убить `git pull` по дедлайну посреди rebase** — `hub_sync` при старте проверяет `.git/rebase-merge|rebase-apply` и делает `rebase --abort`.
- **`self_update` молчит в грязном клоне** (`git status --porcelain` не пуст) — чтобы не дёргать репозиторий разработчика.
- **`help` и `version` обрабатываются до `load_conf`:** именно они объясняют, как чинить сломанный конфиг.
- **Тесты запускаются из репозитория xchg,** поэтому проект сессии по умолчанию — `xchg`. В тестах команды выполняются через `in_api`/`in_web`, которые делают `cd` в песочные репозитории.
- **Правки клиента скриптом делать только с проверкой совпадения** (`assert a in s`): молча не сработавшая замена выглядит как успешный патч, а ловится потом тестом — если тест на это место есть.
- **Регистрация идёт через `hub_push`, а не просто `git add`.** `register_me` и `agent_passport` проверяют `git diff --cached --quiet` перед коммитом: без этого повторный `projects add` создавал бы пустые коммиты.
- **Участие в проектах выводится из каталогов `projects/<p>/<user>/`, а не из колонки в contacts.md.** Ручная колонка врала бы; каталог создаётся вместе с паспортом агента.
