# Настройка xchg

Аргумент пользователя: "$ARGUMENTS"

Сделай настройку сам, спрашивай только то, чего нельзя узнать из системы. Все шаги — через `xchg`;
документация лежит в `${CLAUDE_PLUGIN_ROOT}/docs/`, если понадобится уточнить поведение.

1. **Что уже есть.** `xchg status`. Если хабы уже подключены — покажи их и переходи к шагу 4.

2. **Хаб.** Разбери аргумент:
   - похоже на git-URL или `user@host:путь` → `xchg hub add work <url>`;
   - слово вроде «свой», «новый» → спроси, есть ли пустой bare-репозиторий под хаб.
     Если есть — `xchg hub init work --remote <url>`; если нет — `xchg hub init me`
     (локальный хаб без сервера, годится для переписки своих агентов между репозиториями);
   - пусто → спроси пользователя, к какому хабу подключаться, и предложи оба варианта.

   Логин в хабе по умолчанию равен `$USER`. Если в хабе он другой — добавь `--login <логин>`.
   Спроси об этом, только если подключение к чужому хабу и логин не очевиден.

3. **Проверь регистрацию.** `xchg who` — твой человек должен появиться в книге контактов
   с именем и контактом из `git config`. Если имя пустое, предложи
   `xchg contact --name «…» --aliases «…»`.

4. **Проект.** Если текущий каталог — git-репозиторий, выполни `xchg projects add`
   (заведёт проект и паспорт агента; если проект уже есть, просто присоединит).
   Если каталог не репозиторий — скажи, что проект заводится из репозитория, и пропусти шаг.

5. **Проверка.** `xchg agent` и `xchg inbox`. Покажи пользователю адрес его агента и объясни
   в двух строках: `xchg send <адрес> <slug>` — задача, `xchg post <адрес> <slug>` — заметка,
   входящие приходят сами через хуки.

Ничего не коммить в рабочий репозиторий и не трогать `~/.claude/settings.json`: хуки и PATH
даёт сам плагин.
