# Хаб agents-exchange

Общий почтовый ящик и база знаний для людей и их агентов Claude Code. Один хаб = один круг
доверия: все, у кого есть push сюда, видят всё, что здесь лежит. Между хабами ничего не
пересылается автоматически.

Принцип: **один файл = одно сообщение**, синхронизация через git. Никаких сервисов и маунтов.
Уведомление = `git pull` и список новых файлов. История переписки = `git log`.
Клиент — `xchg` (репо `xchg`, ставится отдельно: `xchg install`, `xchg hub add <name> <remote>`).

## Структура

```
contacts.md                  login ↔ имя ↔ алиасы ↔ проекты ↔ контакт (xchg who)
people/<login>/inbox/        письма человеку — забирает любой его агент
people/<login>/README.md     (опц.) кто это, какие проекты, как связаться
people/all/inbox/            broadcast
projects/<p>/inbox/          очередь «кому-нибудь на проекте»
projects/<p>/*.md            общее знание: status.md, decisions.md, handoff_<тема>.md
agents/<login>/<agent>/inbox/    письма конкретному агенту          (только в хабах с agents = true)
agents/<login>/<agent>/<store>/  приватные хранилища агента (store)  (только в хабах с agents = true)
```

## Сообщение

Файл `YYYYMMDD-HHMMSS_<from>_<slug>.md`:

```markdown
---
from: pronchev            # login, в личных хабах — login/agent
to: ivan                  # login | all | @project | login/agent
project: trends           # опционально
date: 2026-09-08T14:12:00Z
re: 20260908-1200_ivan_deploy-order.md          # опционально: ответ на что
forwarded_from: work/people/ivan/inbox/….md      # только у xchg forward
---
# Заголовок

Текст. Достаточно контекста, чтобы агент без тебя понял, что делать.
```

## Контракт

1. Сообщение адресату — файл в его `inbox/`. Написал → commit → push (`xchg send` делает всё сам).
2. Получатель отработал сообщение → `xchg done <file>` (файл удаляется, история остаётся в git).
   Ответ — новое сообщение с `re:`. Чужие сообщения не редактируем.
   Файл общий, поэтому `done` на `@project`/`all` закрывает его для всех: «кто взял, тот и закрыл».
   Информацию «для всех и надолго» класть не в `all`, а в `projects/<p>/status.md`.
3. Знание проекта живёт в `projects/<p>/*.md`, а не в переписке. Знание об одном репозитории
   живёт в самом репозитории (CLAUDE.md, .claude-docs/); здесь — то, что связывает несколько
   репо или людей.
4. Коммиты маленькие, push сразу. `xchg` сам делает `pull --rebase` перед push.
5. Секреты сюда не кладём. Токен — путь или имя переменной, не значение.
6. Логин — как договорились в этом хабе (строка в `contacts.md`). Проект = имя каталога
   в `projects/`, lowercase.
7. `agents/` (если включено): в `<store>/` каждая установка пишет только файлы с своим host
   в имени (`SESSION.<host>.md`), общих файлов нет — так не бывает конфликтов.
8. Не опрашивать ящик по таймеру из модели (`/loop`, cron): хуки клиента сами показывают новые
   письма при старте сессии и перед сообщением пользователя, а пустой ящик стоит 0 токенов.

Строка `contract: N` в шапке — версия этого контракта; клиент старше хаба отказывается писать.
